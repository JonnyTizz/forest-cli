# Code Review: forest-cli (June 2026)

A review of `forest` against its stated purpose — managing multi-repo git
worktree task workspaces — focused on worktree-state consistency, docs coverage,
and overall usefulness. Items marked **[fixed]** were addressed in this change;
items marked **[noted]** are intentional or deferred, with rationale.

## Worktree-state consistency bugs

### 1. Existing-branch checkout checked out the base, not the branch — [fixed]
`workspace.Create` + `gitx.WorktreeAdd`. When the task branch already existed,
the code passed an empty new-branch and the *base* as the checkout target, so
`git worktree add <path> <base>` ran. Git would either fail ("base already
checked out") or silently put the worktree on the base while the metadata
recorded the task branch — after which `task remove` deleted the wrong branch.
`WorktreeAdd` now takes an explicit `checkout` argument and the existing-branch
path runs `git worktree add <path> <branch>`. Regression test:
`gitx.TestWorktreeAddNewAndExistingBranch`, `workspace.TestCreateExistingBranchIsCheckedOut`.

### 2. A failed `create` left an unremovable task — [fixed]
If `writeMeta`, agent rendering, or env sync failed, there was no rollback and
(for `writeMeta`) no metadata file. The directory existed, so `create` reported
"already exists", but `list` skipped it and `remove` failed reading metadata.
`Create` now rolls back on every post-worktree failure, and the new
`forest doctor` command finds and removes such orphans if one ever slips
through. Test: `workspace.TestRollbackPreservesExistingBranch`, `TestOrphans`.

### 3. Rollback force-deleted pre-existing branches — [fixed]
On a mid-create failure, rollback ran `git branch -D <branch>` for every repo it
touched, including repos where the branch already existed and was merely checked
out — destroying a user's branch. Rollback now tracks, per worktree, whether it
created the branch, and only deletes those. Test:
`workspace.TestRollbackPreservesExistingBranch` asserts the pre-existing branch survives.

### 4. `remove` deleted the task dir even when worktree removal failed — [fixed]
A failed `WorktreeRemove` was only a warning; the code then pruned (a no-op while
the directory still existed) and `os.RemoveAll`'d the contents anyway, orphaning
git's `.git/worktrees/<id>` metadata. Now, without `--force`, a failed worktree
removal aborts before the directory is deleted, and pruning happens *after*
removal. Test: `workspace.TestRemoveRefusesDirty` (and the clean path in
`TestCreateAndRemove`).

### 5. "Unpushed" check scanned all branches, not the task's — [fixed]
`HasUnpushed` used `git log --branches --not --remotes`, so a local `main` ahead
of `origin/main` blocked removing any unrelated task in that repo. It is now
scoped to `HEAD`. Test: `gitx.TestHasUnpushedScopedToHEAD`.

### 6. TUI deleted on a single keypress and corrupted its own screen — [fixed]
`d` removed a task immediately, and `workspace.Remove` wrote warnings to stderr,
garbling the Bubble Tea alt-screen. `d` now prompts `y/N`, and `Remove` returns
warnings to the caller instead of printing them.

## Smaller correctness issues

- **Dead branch in `gitx.Stat`** (`y != 0` on a byte from a string) — [fixed], simplified.
- **No-op `.git/info/exclude` write in `init`** — [fixed]. The worktrees dir
  lives at the project root, never inside a repo, so excluding it from each
  repo did nothing; removed (and the now-unused `IgnoreInExclude` helper).
- **`default_base` hardcoded to `main`** — [fixed]. `init` now detects each
  repo's real default branch via `gitx.DefaultBranch`, so `master` repos work.
- **`truncate` could split a UTF-8 rune** in `task status` — [fixed], now
  counts/slices by rune.
- **`os.Exit(2)` in `env diff`** bypassed normal teardown — [fixed], routed
  through a typed `ExitCodeError` handled in `Execute` (still exits 2 on drift).
- **Unvalidated branch/base names** — [fixed]. `workspace.ValidateRef` rejects
  refs that start with `-`, contain whitespace/git-special characters, or
  contain `..`, closing the git-option-injection gap noted in the security audit.
- **Stale base** (worktrees fork from the local base with no fetch) — [noted].
  This is now documented in the README as a known footgun; a `--fetch` flag is a
  reasonable future addition.

## Security audit follow-up (`security.md`)

The audit's findings were re-verified against the code. Two were fixed here and
the audit was corrected for accuracy (it referred throughout to `forest.yaml`;
the real config is `.forest/config.yaml`, and its summary table was misnumbered):

- **#1 `$EDITOR` shell injection** — [fixed]. `config edit` no longer builds an
  `sh -c` string; `runner.SplitArgs` parses `$EDITOR` and the editor runs via
  `exec.Command` with the path as a separate argv element.
- **#2 / #8 env-file path traversal** — [fixed]. `envfiles.containedUnder`
  rejects absolute `source`/`dest` and `..` escapes. Test:
  `envfiles.TestSyncRejectsEscapingPaths`.
- **#3 unvalidated `Repo.Path`** — [noted, by design]. Repos legitimately live
  outside the project (absolute paths are a supported config option), and
  `git worktree remove` only removes *registered* worktrees, so the practical
  risk is low. The trust model is documented: run `forest` only against configs
  you trust.
- **World-readable `0o644` files** — [noted]. Unchanged; the concrete risk is
  synced env-file copies, which inherit whatever mode is appropriate for your
  environment. Tightening to `0o600` for synced secrets is a reasonable option.

## Usefulness

Added:
- **`forest task path`** — print a workspace path for `cd "$(forest task path x)"`;
  there was previously no ergonomic way to enter a workspace.
- **`forest doctor [--fix]`** — surface and repair orphaned task dirs and stale
  worktree entries; directly mitigates the class of bug in #2/#4.
- **`forest config edit config`** — edit and re-validate `.forest/config.yaml`
  (previously only the agents fragments were editable).

### The TUI is a core part of the tool

The CLI is the scriptable engine; the TUI (`forest tui`) is the human
front-end. It's the one place you see every task's worktree state — branch,
base, ahead/behind, dirty counts — at a glance and act on it, with two in-scope
actions: env sync (`s`) and remove (`d`, now with a `y/N` confirmation). That's
squarely within the tool's scope (managing worktrees across related repos) and
is the only navigable, all-tasks view, so it complements rather than duplicates
`list`/`status`. Agent launching is intentionally not part of it — that's
delegated to dedicated tools (Claude Code / opencode), with `forest agent start`
as the CLI handoff.

Optional in-scope ideas, if it's ever extended: create a task from the TUI, and
an "open editor / cd to worktree" action. Both are worktree-facilitation, not
agentic — no agent launching.

## Testing

The repo had **no tests**. Added unit/integration coverage for `gitx` (real temp
repos), `envfiles` (sync/diff/force/escape matrix), `workspace`
(create/remove/rollback/orphans with two temp repos), `runner.SplitArgs`, and
`config.Validate`. `go test ./...` is green.
